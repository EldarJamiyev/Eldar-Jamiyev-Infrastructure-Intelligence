# Ruflo — Multi-Agent Swarm Orchestration & Distributed Intelligence

Ruflo provides an enterprise-grade swarm orchestration framework for managing cooperating autonomous agents in mission-critical environments. In the EJII (Eldar Jamiyev Infrastructure Intelligence) architecture, Ruflo powers the **5-Agent SRE War Room** and coordinates distributed diagnostic probes without race conditions or deadlocks.

---

## 🐝 Core Swarm Topologies

Ruflo supports three primary agent swarm topologies:

```
1. Hierarchical (Commander & Specialists):
       [ Commander Agent ]
        /        |        \
   [ Triage ] [ Network ] [ Security ]

2. Mesh / Consensus (Peer-to-Peer):
   [ Agent A ] <---> [ Agent B ]
        ^                 ^
        |                 |
        v                 v
   [ Agent C ] <---> [ Agent D ]

3. Pipeline (Assembly Line):
   [ Ingestion ] -> [ Analysis ] -> [ Remediation ] -> [ Audit ]
```

## 🛠️ Key Capabilities & Protocols

### 1. Dynamic Task Dispatching & Load Balancing
- Distributes diagnostic workloads across heterogeneous subagent workers based on current memory headroom, CPU affinity, and role clearance (RBAC).
- Prevents worker starvation using priority queues with bounded aging.

### 2. Multi-Agent Consensus & Cross-Examination
- **Quorum-Based Agreement**: Before taking high-impact remediation actions (e.g. interface reset, route table flush), a minimum $k$-of-$n$ consensus is mandated.
- **Adversarial Cross-Examination**: The *Doubt-Driven Critic Agent* actively attempts to invalidate hypotheses generated by the *Triage Agent* using empirical probe data.

### 3. Self-Healing & Crash Recovery
- Heartbeat watchdog monitors agent conversation threads.
- If an agent crashes or times out during a packet dissection or trace analysis, Ruflo restarts the worker with preserved episodic state from SQLite WAL.

## 💻 EJII Integration Patterns

### Pattern A: Spawning the 5-Agent SRE War Room
```javascript
import { SwarmCoordinator } from './core/swarm-coordinator.js';

const warRoom = new SwarmCoordinator({
  topology: 'hierarchical',
  commander: 'incident-commander',
  specialists: [
    { role: 'wire-analyst', toolAccess: ['wireshark_dissect', 'pcapng_engine'] },
    { role: 'topology-investigator', toolAccess: ['spectral_gnn', 'routing_radix'] },
    { role: 'kernel-inspector', toolAccess: ['host_metrics', 'sysinternals_forensics'] },
    { role: 'safety-officer', toolAccess: ['dsrl_vault', 'lyapunov_gate'] }
  ],
  consensusThreshold: 0.75,
  maxRounds: 4
});

const consensusResult = await warRoom.deliberate({
  incidentId: 'INC-2026-8812',
  symptoms: ['Gateway packet drop > 8%', 'TCP SYN retry spikes on port 443']
});
```

### Pattern B: Byzantine Fault-Tolerant Action Voting
```javascript
// Ensure no single agent can trigger an invasive network configuration change
const vote = await warRoom.voteOnRemediation({
  action: 'FLUSH_ARP_CACHE_AND_RENEW_DHCP',
  targetInterface: 'Ethernet0',
  safetyTier: 2
});

if (vote.approved && vote.lyapunovDescentVerified) {
  await executionEngine.dispatch(vote.scriptId);
} else {
  logger.warn('Remediation rejected by consensus or Lyapunov safety gate');
}
```

## 📋 Best Practices
- Never allow worker agents to bypass the Central Safety Officer or Lyapunov Vault.
- Keep agent context payloads concise; summarize intermediate steps using linguistic root compression (Caveman pattern).
- Log all inter-agent messages and vote tallies to the cryptographic HMAC-SHA256 audit ledger.
